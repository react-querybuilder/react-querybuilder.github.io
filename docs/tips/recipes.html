Recipes

Every snippet on this page was run against the current source and the output shown is exact. All snippets work on the server with @react-querybuilder/core (react-querybuilder re-exports the same functions). See Export and Import for full option references.

Shared setup​

The export recipes use this query and fields:

import type { Field, RuleGroupType } from '@react-querybuilder/core';

const fields: Field[] = [
  { name: 'firstName', label: 'First name' },
  { name: 'lastName', label: 'Last name' },
  { name: 'age', label: 'Age', inputType: 'number' },
  { name: 'isMusician', label: 'Is a musician', valueEditorType: 'checkbox' },
];

const query: RuleGroupType = {
  combinator: 'and',
  rules: [
    { field: 'firstName', operator: 'beginsWith', value: 'Stev' },
    { field: 'age', operator: 'between', value: [18, 65] },
    {
      combinator: 'or',
      rules: [
        { field: 'lastName', operator: 'in', value: ['Vai', 'Vaughan'] },
        { field: 'isMusician', operator: '=', value: true },
      ],
    },
  ],
};

Export (formatQuery)​

sql​

Inline values. Not for untrusted input; prefer parameterized. Add parseNumbers: true to emit unquoted numbers.

import { formatQuery } from '@react-querybuilder/core';

formatQuery(query, 'sql');
Output
(firstName like 'Stev%' and age between '18' and '65' and (lastName in ('Vai', 'Vaughan') or isMusician = TRUE))

parameterized​

import { formatQuery } from '@react-querybuilder/core';

formatQuery(query, 'parameterized');
Output
{
  "sql": "(firstName like ? and age between ? and ? and (lastName in (?, ?) or isMusician = ?))",
  "params": ["Stev%", 18, 65, "Vai", "Vaughan", true]
}

parameterized_named​

import { formatQuery } from '@react-querybuilder/core';

formatQuery(query, 'parameterized_named');
Output
{
  "sql": "(firstName like :firstName_1 and age between :age_1 and :age_2 and (lastName in (:lastName_1, :lastName_2) or isMusician = :isMusician_1))",
  "params": {
    "firstName_1": "Stev%",
    "age_1": 18,
    "age_2": 65,
    "lastName_1": "Vai",
    "lastName_2": "Vaughan",
    "isMusician_1": true
  }
}

mongodb_query​

    { "age": { "$gte": 18, "$lte": 65 } },
    { "$or": [{ "lastName": { "$in": ["Vai", "Vaughan"] } }, { "isMusician": true }] }

elasticsearch​

Experimental.

import { formatQuery } from '@react-querybuilder/core';

formatQuery(query, 'elasticsearch');
Output
{
  "bool": {
    "must": [
      { "regexp": { "firstName": { "value": "Stev.*" } } },
      { "range": { "age": { "gte": 18, "lte": 65 } } },
      {
        "bool": {
          "should": [
            {
              "bool": {
                "should": [{ "term": { "lastName": "Vai" } }, { "term": { "lastName": "Vaughan" } }]
              }
            },
            { "term": { "isMusician": true } }
          ]
        }
      }
    ]
  }
}

qdrant​

Experimental. Qdrant Filter for vector search metadata filtering. String ops other than contains (full-text match.text) are skipped.

import { formatQuery } from '@react-querybuilder/core';

formatQuery(query, 'qdrant');
Output
{
  "must": [
    { "key": "firstName", "match": { "prefix": "Stev" } },
    { "key": "age", "range": { "gte": 18, "lte": 65 } },
    {
      "should": [
        { "key": "lastName", "match": { "any": ["Vai", "Vaughan"] } },
        { "key": "isMusician", "match": { "value": true } }
      ]
    }
  ]
}

pinecone​

Experimental. Pinecone metadata filter. String ops skipped; not groups via De Morgan.

    { "age": { "$gte": 18, "$lte": 65 } },

import { Op } from 'sequelize';

Returns a Sequelize where object (Op from sequelize).

Import (parsers)​

Parsers return a RuleGroupType without ids. Most parsers return list values (in, between) as comma-separated strings unless you pass { listsAsArrays: true }. Pass { fields } to drop unknown fields, and { independentCombinators: true } for RuleGroupTypeIC. Use prepareRuleGroup before passing the result to a controlled <QueryBuilder query>.

parseSQL​

import { parseSQL } from '@react-querybuilder/core/parseSQL';

parseSQL(
  "SELECT * FROM t WHERE firstName LIKE 'Stev%' AND (lastName IN ('Vai', 'Vaughan') OR age BETWEEN 18 AND 65)"
);
Output
{
  "combinator": "and",
  "rules": [
    { "field": "firstName", "operator": "beginsWith", "value": "Stev" },
    {
      "combinator": "or",
      "rules": [
        { "field": "lastName", "operator": "in", "value": "Vai, Vaughan" },
        { "field": "age", "operator": "between", "value": "18, 65" }
      ]
    }
  ]
}

parseSPARQL​

Only FILTER conditions are kept; variables keep their ? prefix.

import { parseSPARQL } from '@react-querybuilder/core/parseSPARQL';

parseSPARQL(
  'SELECT ?p WHERE { ?p ex:age ?age . FILTER(STRSTARTS(?firstName, "Stev") && ?age >= 18) }'
);
Output
{
  "combinator": "and",
  "rules": [
    { "field": "?firstName", "operator": "beginsWith", "value": "Stev" },
    { "field": "?age", "operator": ">=", "value": 18 }
  ]
}

JSON Schema (getQueryJsonSchema)​

JSON Schema for queries matching fields, for LLM structured output/tool inputs or Ajv. Loose mode shown for brevity; the default full mode also constrains operators and values per field. Check the result with the diagnostics format. See JSON Schema.

import { getQueryJsonSchema } from '@react-querybuilder/core';

getQueryJsonSchema(fields, { mode: 'loose', operators: ['=', 'in'] });
Output
{
  "$defs": {
    "group": {
      "type": "object",
      "properties": {
        "combinator": { "type": "string", "enum": ["and", "or"] },
        "rules": {
          "type": "array",
          "items": { "anyOf": [{ "$ref": "#/$defs/rule" }, { "$ref": "#/$defs/group" }] }
        },
        "not": { "type": "boolean" }
      },
      "required": ["combinator", "rules"]
    },
    "rule": {
      "type": "object",
      "properties": {
        "field": { "type": "string", "enum": ["firstName", "lastName", "age", "isMusician"] },
        "operator": { "type": "string", "enum": ["=", "in"] },
        "value": {}
      },
      "required": ["field", "operator", "value"]
    }
  },
  "$ref": "#/$defs/group"
}
